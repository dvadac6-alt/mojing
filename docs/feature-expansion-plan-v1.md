# 墨境 · 功能扩展计划 v1

> 2026-08-22 起，在 v4 优化计划（#1–#10 全部落地）基础上新增的功能路线图。
> 原则：**一个功能一个功能慢慢实现**，每项完成后在第六节打卡记录，再启动下一项。
> 所有方案均已对照现有代码（`app/models.py` / `app/routers/` / `src/hooks/useEntityList.ts` / `FormFooter`）校验过集成点。

---

## 一、目标与定位

v4 解决的是"跑得快、跑得稳"，本计划解决"还能多做什么"。三个方向：

1. **强化核心卖点**（长篇一致性）：章节摘要链、角色登场追踪、时间线 —— 与伏笔追踪同一叙事，"防遗忘"全家桶
2. **网文作者刚需**：发布前自检、专注模式、灵感收集箱、命名生成器
3. **AI 与分发深化**：自定义 Prompt 模板、文风分析、多角色对话、EPUB 导出、WebDAV 备份

## 三、实施顺序

```
第一批（核心一致性）：F1 摘要链 → F2 登场追踪 → F3 发布自检
第二批（体验小步快跑）：F4 专注模式 → F6 Prompt 模板 → F7 EPUB → F5 灵感箱
第三批（结构化深化）：F8 时间线 → F10 对话生成 → F9 命名生成器
第四批（进阶）：F11 文风分析 → F12 WebDAV
```

排序依据：F1 是 F8 的事件抽取素材和续写上下文的地基，最先做；F2/F3 零依赖、高感知；第二批全是小体量快速见效；F8 最大放第三批开头，此时 F1 已就位。

## 四、通用约定（每个功能都遵守）

- **建表/加列**：新表加进 `app/models.py`（`Base.metadata.create_all` 自动建）；已有表加列走 `database.py::_migrate_legacy_columns()` 模式。**所有外键必须带 `ondelete="CASCADE"`**（`database.py` 有孤儿记录防护，裸 SQL 建表会被卡）。
- **前端实体列表**：新实体一律走 `useEntityList(novelId, kind)` 模式（模块级缓存 + 请求去重）；mutations 后 patch 局部状态，不整包重拉 workspace。
- **表单弹窗**：底栏复用 `FormFooter`。
- **类型同步**：新增/修改端点后跑 `npm run gen:types`。
- **测试**：后端逻辑进 `backend/tests/`（pytest）；前端可测纯函数抽到 `src/lib/` 配 `*.test.ts`（node:test）。
- **AI 新动作**：统一复用 `app/routers/ai.py` 的 `_prepare_generation` 注入链路与 SSE 通道，不另起 provider 调用。
- **验收基线**：pytest + test:ui + typecheck + lint + build 全绿，才算一项完成。

## 五、功能详细设计

### F1 章节摘要链（滚动前情提要）⭐ P0

**问题**：RAG 是片段级召回，擅长"找回某个细节"，但续写时缺一条连贯的"故事主线"。上下文窗口装不下前文全文时，剧情连贯性只能靠运气。

**方案**：每章一份 200–300 字摘要；续写时上下文 = 最近 K 章全文 + 更早章节摘要串，由服务端按字数预算动态拼装。

**数据模型**（迁移加列）：

```
chapters 新增：
  summary: Text, default ""       # AI 生成或手写的章节摘要
  summary_generated_at: DateTime? # 摘要生成时间，内容更新早于此则视为过期
```

**API**：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/novels/{nid}/chapters/{cid}/summarize` | AI 生成摘要并写回（SSE 流式，复用 generate 链路，非流式亦可） |
| GET | `/api/novels/{nid}/recap?before_chapter_id=&budget=4000` | 拼装滚动提要：该章之前最近 K 章取标题+结尾段，更早取 summary 串，超预算从最旧开始截断 |

**前端**：
- 写作页章节头部菜单加"生成摘要"；已有摘要显示摘要文本（可编辑，走现有章节更新接口）
- AI 面板上下文勾选区新增"前情提要"（默认勾选），请求时附 `before_chapter_id`

**集成**：`_prepare_generation` 中当勾选 recap 时注入 `## 前情提要` 段。

**实现步骤**：
1. 迁移加列 + schemas 更新
2. recap 拼装函数（纯函数，pytest 单测：预算截断、无摘要降级为标题串）
3. summarize 端点（prompt：压缩剧情要点、保留人物与伏笔变化）
4. 前端按钮 + AI 面板勾选 + 注入
5. `gen:types`

**验收**：生成摘要可存可重生成可手改；续写请求 messages 含前情提要段；全库无摘要时降级不报错。

### F2 角色登场追踪 ⭐ P0

**问题**：配角一多就"消失"——重要角色 15 章没出场读者早忘了。和伏笔超期提醒同构的痛点。

**方案**：章节保存时扫描正文命中角色名/别名，记录登场矩阵；对"主要角色长时间未登场"给出提醒。

**数据模型**（新表）：

```
character_appearances:
  id: str PK
  novel_id: FK→novels, CASCADE
  character_id: FK→characters, CASCADE
  chapter_id: FK→chapters, CASCADE
  hits: int                # 本章命中次数
  created_at: DateTime
  约束: UNIQUE(character_id, chapter_id)
```

**扫描时机**：`PUT /chapters/{cid}` 保存时同步重扫该章（先删旧记录再插入；正文是纯文本，`name + aliases.split(/[,，、\s]+/)` 直接 contains，**按名称长度降序匹配**避免"江离"/"江离别"误吞）。角色改名/加别名时对该小说全量重扫一次。

**API**：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/novels/{nid}/characters/presence` | 每角色：首末登场章节、距最新章的空窗章数、登场章节 id 列表 |
| POST | `/api/novels/{nid}/characters/rescan` | 全量重扫（修数据/初次启用用） |

**前端**：
- 角色卡片显示"最近登场 第N章 · 已空窗 X 章"（空窗超过阈值标警示色）
- 概览页提醒区与伏笔超期提醒并列："以下主要角色超过 N 章未登场"
- 阈值进设置页（默认 10 章）

**实现步骤**：建表 → 保存钩子扫描（扫描函数抽纯函数进 pytest）→ presence 聚合端点 → rescan → 前端卡片/概览/设置 → `gen:types`。

**验收**：保存章节后登场记录即时更新；删除角色/章节无孤儿记录；别名命中正确；空窗提醒出现且阈值可改。

### F3 发布前自检（敏感词/规范检查）⭐ P0

**问题**：发布到起点/番茄前的两大隐性成本——违禁词导致锁章，低级错字伤读者体验。目前只能靠外部工具。

**方案**：纯本地词库 + 规则引擎，一键出报告，可跳转到文内位置。不依赖 AI、不发网络请求。

**检查规则**（四类）：
1. **敏感词**：内置基础词库（随包分发），用户可在设置页导入自定义词库追加（存 `DATA_DIR/wordlists/`）
2. **叠字重复**："的的""了了""在在""是是" 等相邻重复
3. **标点规范**：连续感叹/问号 >3；中英标点紧邻混用（如 `",。"` `”。`）；引号不配对
4. **可选 AI 深查**：报告底部入口跳转现有 check-consistency

**API**：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/novels/{nid}/chapters/{cid}/lint` | 单章检查，返回 `[{type, word, offset, message}]` |
| POST | `/api/novels/{nid}/lint` | 全书批量（按章分组汇总，供发布前整书体检） |
| POST | `/api/system/wordlists/import` | 上传自定义词库（每行一词） |

**前端**：写作页工具栏"自检"按钮 → 右侧报告面板（按类型分组、计数徽章），点击条目编辑器滚动到对应 offset 并高亮；设置页词库管理（查看内置/导入/清空自定义）。

**实现步骤**：
1. lint 核心抽纯函数（`app/services/lint.py`，规则 1–3 全部 pytest 覆盖，offset 精确性是重点）
2. 内置词库文件打包 + 首次启动释放到 DATA_DIR
3. 两个 lint 端点 + 词库导入端点
4. 前端报告面板与跳转高亮
5. 设置页词库管理

**验收**：构造含四类问题的样例章全部命中且 offset 正确；自定义词库导入后立即生效；10 万字单章 lint 耗时可接受（<1s 量级，必要时按行扫描）。

### F4 专注模式 P1 · S

**方案**：纯前端。写作页全屏 overlay：只剩正文、实时字数、本次目标进度、退出按钮。

- **进入**：写作页工具栏"专注模式"或快捷键 F11
- **打字机滚动**：光标保持视口垂直中央（可开关）
- **本次目标**：进入时设定本次字数（默认 1000），进度条 + 达成轻提示
- **退出**：ESC / 右上角按钮

**实现步骤**：Overlay 组件（复用现有编辑器实例，不重挂载）→ 打字机滚动（监听 selection update，scrollIntoView 中央）→ 目标进度。状态存 sessionStorage，不进后端。

**验收**：进退出无状态丢失（草稿不丢）；打字机滚动平滑；达成目标有提示。

### F5 灵感收集箱 P1 · S-M

**问题**：灵感总在非写作时刻出现（通勤/睡前），没处放，转头就忘。

**方案**：全局侧栏抽屉，随手记；之后一键转化为结构化实体（角色/伏笔/大纲节点/章节）。

**数据模型**（新表）：

```
ideas:
  id: str PK
  novel_id: FK→novels, CASCADE, 可空（NULL = 全局灵感）
  content: Text
  status: inbox / converted / discarded
  converted_kind: str?   # character / thread / outline / chapter
  converted_id: str?
  created_at / updated_at
```

**API**：CRUD `/api/ideas`（`?novel_id=` 过滤，不传含全局）+ `POST /api/ideas/{id}/convert`（body 指定 kind 与目标表单数据；服务端调用对应创建逻辑后回写 status/converted_id）。

**前端**：
- 侧栏常驻"灵感箱"入口（角标显示 inbox 数），抽屉内快速输入 + 列表
- 每条灵感操作：转为伏笔/角色/大纲节点/章节（弹出对应现有创建表单，预填 content 到 description）→ 成功后标记 converted 并可点击跳转

**验收**：无选中作品时可记全局灵感；转化链路四类目标全部走通并跳转；删除小说级联清理其 ideas（全局的不受影响）。

### F6 自定义 Prompt 模板 P1 · S

**问题**：AI 面板只有固定动作（续写/润色/扩写/方向），用户反复手打的私有指令（"这段对话改得更口语""增加环境描写"）没处沉淀。

**数据模型**（新表）：

```
prompt_templates:
  id: int PK
  name: str(60)
  content: Text           # 支持 {selection} 占位符 = 当前选中文本
  created_at / updated_at
```

**API**：CRUD `/api/prompt-templates`。

**前端**：
- AI 面板新增"自定义"页签：模板列表（管理：增删改，在设置页亦可管理）
- 点击模板 → 面板进入自定义模式，content 中 `{selection}` 替换为选中文本，无选中则提示先选段
- 生成走现有 `/ai/generate` SSE 链路，不新增 AI 端点

**验收**：模板 CRUD；占位符替换正确；生成/插入/拒绝流程与内置动作一致。

### F7 EPUB 导出 P1 · S

**现状**：`export_novel` 已支持 txt / markdown / docx（python-docx），缺设计方案里承诺的 EPUB。

**方案**：
- 依赖：`ebooklib`（纯 Python，PyInstaller 打包无 hidden import 风险）
- `ExportRequest.fmt` 增加 `epub` 分支：书名/作者做元数据，章节为 spine + toc，Scene 作为章内小节标题（有 scenes 时）
- 封面：暂用生成的纯色占位封面（写书名+作者），不做封面上传（如需，后续小迭代）

**实现步骤**：requirements.txt + ebooklib 分支 + 样式（段落间距、首行缩进的内置 CSS）→ 导出按钮下拉补 EPUB。

**验收**：Calibre / Apple Books / 微信读书导入打开正常，目录层级正确；空章节/特殊字符书名不崩；导出 zip（备份）流程不受影响。

### F8 时间线/大事记 ⭐ P1 · L（建议 F1 之后做）

**问题**：长篇第三大遗忘点——时间。角色年龄、季节、事件先后全靠脑子记；check-consistency 目前没有时间维度。

**关键设计决策**：故事内时间**用自由文本**（"第三年春""大战后三日"）+ **章节锚点**（挂在哪章/计划挂哪章），不做结构化历法。网文时间体系千奇百怪（修炼纪年/架空历法），强制结构化是伪需求；排序一律按章节顺序，故事内时间只做展示。

**数据模型**（新表）：

```
timeline_events:
  id: str PK
  novel_id: FK→novels, CASCADE
  title: str(200)
  description: Text, default ""
  story_time: str(60)        # 故事内时间，自由文本
  chapter_id: FK→chapters, CASCADE, 可空（NULL = 计划中/未定位）
  order_hint: int            # 同章内多个事件的排序
  created_at / updated_at
```

**API**：CRUD `/api/novels/{nid}/timeline-events`（列表默认按 chapter.order + order_hint 排序，未挂章的排在最前标"计划中"）。

**前端**：新页面 `/novels/:id/timeline`，侧栏入口：
- 垂直时间轴按章分组，事件卡片显示 story_time / 标题 / 描述摘要 / 关联章节链接（点击跳写作页）
- 未挂章的"计划中"事件置顶区
- AI 辅助抽取（F1 就绪后）：选择若干章 → AI 从正文/摘要生成事件草稿 → 用户勾选入库

**AI 集成**：
- `_prepare_generation` 勾选项新增"时间线"：注入当前章前后各 N 章挂载的事件
- check-consistency 增加时间维度：事件序列（章序 + story_time）交给 AI 找先后矛盾

**实现步骤**：建表 + CRUD → 时间轴页面 → 上下文注入 → 一致性检查扩展 →（可选）AI 事件抽取。分两批提交：先 CRUD+页面，再 AI 集成。

**验收**：事件 CRUD 与分组渲染正确；跳转章节正常；注入与一致性检查包含时间线数据；删除章节时挂载事件级联删除（或按需转"计划中"——实现时二选一，写进代码注释）。

### F9 命名生成器 P2 · S

**方案**：本地规则组合生成（无 AI、零延迟），类别：人名（姓+双字名）、地名、门派/势力、功法/技能、丹药/法宝。词库 JSON 随包内置，`DATA_DIR` 下同名文件存在则覆盖扩展。

**API**：`GET /api/tools/names?kind=person&count=10` → 本地随机组合（同批去重）。可选后续：`POST /api/tools/names/ai`（带上下文让 AI 起名，标注"消耗 token"）。

**前端**：写作页工具栏"起名"小弹窗：选类别 → 批量生成 → 点击复制 / 直接填入当前选中实体表单。

**验收**：五类各自生成合理结果且同批不重复；自定义词库文件生效。

### F10 多角色对话生成 P2 · S-M

**方案**：AI 面板新动作"对话"：勾选 2–4 个角色 + 一句场景描述（"在酒楼谈判破裂"）→ 生成一段多角色对话。

**实现**：`ai.py` 加薄端点 `POST /api/ai/dialogue`——复用 `_prepare_generation` 的注入逻辑（所选角色全卡 + 相互关系 + 相关设定），prompt 明确要求按性格区分声口、只输出对话场景。SSE 复用现有流式响应。

**前端**：AI 面板加"对话"页签：角色多选（复用 ModelSelect 风格）、场景输入框、生成结果与其他动作一致的插入/拒绝流程。

**验收**：对话明显体现所选角色 personality 差异；流式正常；未选足 2 人时按钮禁用。

### F11 文风分析与保持 P2 · M

**问题**：AI 续写最大的抱怨是"AI 味"——句式整齐、对话过密、描写空洞。与其换模型，不如把**作者自己的文风指标**量化后喂给模型。

**指标**（基于已写正文计算）：
- 句长：均值 / 中位数 / P90
- 对话行占比（含引号行 / 总行）
- 段落长度分布
- 高频词 Top20（去停用词）
- 逗号密度、感叹/问号频率

**API**：
- `POST /api/novels/{nid}/style-profile?scope=recent_20` → 计算并写回 `novels.style_profile`（JSON 列，迁移加列）
- 指标计算抽纯函数进 pytest（边界：空章、纯对话章）

### F12 WebDAV 自动备份 P2 · M

**问题**：本地优先 ≠ 只有一份。多设备（台式机+笔记本）目前靠手动导出迁移 zip。

**方案**：可选配置 WebDAV 目标（坚果云/NAS 均可），每日备份完成后自动上传，远端保留最近 N 份轮换。

**实现**：
- 配置存 `ai_configs` 同款的加密机制（`security.py` 现有加密函数），密码加密落库、响应只回掩码
- 传输用 **httpx**（已有依赖）：PUT 上传、PROPFIND/DELETE 做远端轮换，无需新依赖
- 触发点：`backup.py` 每日备份成功后 fire-and-forget 上传，失败写日志（RotatingFileHandler 已就位），不阻塞备份流程
- 设置页：WebDAV 表单（URL/账号/密码）+ "测试连接" + "立即上传" + 远端备份列表（可选）

**验收**：测试连接成功/失败信息透传；每日备份后自动上传且远端只留 N 份；凭据在 DB 中为密文、API 响应为掩码；断网时仅记日志不影响本地备份。

### 2026-08-23 设置页 UI 重排（修复遮挡）

用户反馈设置界面有遮挡。定位出三层根因并全部修复：

1. **应用根布局 `min-width: 1024px`**（`.desktop`）——窗口小于 1024 时整个应用画布右溢出被裁切，设置页右侧控件（阈值/字号/开关）正好在被裁区域。改为 `min-width: 860px`，并在 `@media (max-width: 1080px)` 下把 `.setting-block` 从「左标题右面板」两列改为单列堆叠。
2. **通用/编辑器分区复用了写作页工具栏的 `.font-steps`**（固定 30px 按钮、值用 `<b>` 无垂直居中）和 `.setting-row`（内联 padding 归零导致内容贴面板边框）。重写为设置页专用组件 `PrefRow` + `.pref-*` 样式族：`.pref-segments`（自适应宽分段选择：字号/保存间隔）、`.pref-stepper`（＋ 值 － 步进器，等宽数字、到下限禁用减号）、`.setting-pad`（面板内边距）、`.pref-note`（全宽提示条替代原「数据与隐私」空块）。
3. **内容包裹层 `maxWidth: 720` 在窄容器下溢出**——改为 `min(720px, 100%)`（设置页 7 处统一）。

顺带修复：WebDAV 表单输入框贴面板边框（套 `.setting-pad`）；AI 模型弹窗内「设为当前使用模型」行统一为 `PrefRow`；空窗阈值说明文案由「左键 +1，右键 -1」改为与实际 ＋/－ 按钮一致。
